# מטאפורה

ניהול פנימי לבר-קפה מטאפורה בירושלים: תזרים, משימות ואנשי קשר.

האתר בעברית, מימין לשמאל. אין כניסה עם סיסמה. שלושת השותפים משתמשים בו ביחד.

## הרצה מקומית

```bash
npm install
npm run dev
```

בלי קובץ `.env.local` הנתונים נשמרים בדפדפן הזה בלבד (localStorage, מפתח `metaphora.v1`). אפשר לעבוד כך עד שמחברים מסד.

## מסד נתונים

צרו פרויקט Supabase **חדש** לחשבון של העסק. אל תשתמשו בפרויקט של ברוק.

1. הריצו את `supabase/schema.sql` בעורך ה-SQL.
2. העתיקו את `.env.example` ל-`.env.local` ומלאו:

```
VITE_SUPABASE_URL=https://your-project.supabase.co
VITE_SUPABASE_ANON_KEY=your-anon-key
```

3. הריצו `npm run dev` **מהמחשב הזה** פעם אחת. הפתיחה הראשונה מול המסד הריק מכניסה את השותפים, הקטגוריות, משימות ההקמה, ואת אנשי הקשר מהקובץ המקומי.

קבצים ותמונות (קבלות, תמונות למשימות) עולים ל-bucket בשם `attachments`.

## עדכון מסד קיים — תתי משימות

לפני פריסת הגרסה עם תתי המשימות, הריצו בעורך ה-SQL של Supabase את
`supabase/migrations/202611220001_task_subtasks.sql`. הנתונים הקיימים נשמרים;
למשימות הקיימות מתווספת רשימה ריקה. במסד חדש `schema.sql` כבר כולל את העדכון.

אפשר להוסיף, לערוך ולמחוק תתי משימות בחלון עריכת המשימה ולשמור את הרשימה
בכפתור השמירה. סימון תת משימה ברשימה הראשית נשמר מיד ברקע. השלמת הרשימה
אינה סוגרת אוטומטית את המשימה הראשית.

## מה נטען בהתחלה

- שותפים: גלעד, נועם, אריאל. אפשר לשנות בהגדרות.
- קטגוריה אחת משותפת לתזרים ולמשימות. העמודות מהגיליון "מטאפורה", ואחריהן חוזה, שיפוצים, צוות. שוטף כבר מופיע בגיליון.
- 51 משימות פתוחות מהגיליון "מטאפורה". נושא שהוא `(שם)` משויך לשותף. `כולם` משויך לשלושת השותפים. דחיפות ברירת מחדל: בינונית.
- הגיליון הראשון (`גיליון1`) לא יובא, כדי לא לכפול משימות.
- אנשי קשר מהטבלאות בתחתית אותו גיליון יושבים בקובץ `src/data/contacts.local.ts`. הקובץ לא נכנס ל-git כי המאגר ב-GitHub ציבורי ויש בו טלפונים ומיילים.

## פריסה

לא פרסתי כלום.

אחרי שאתם מרוצים, פותחים חשבון Cloudflare **חדש** לעסק (לא החשבון שמחובר עכשיו במחשב). ב-GitHub Actions של המאגר מוסיפים secrets:

- `CLOUDFLARE_API_TOKEN` — טוקן מהחשבון החדש, עם הרשאת Cloudflare Pages
- `CLOUDFLARE_ACCOUNT_ID`
- `VITE_SUPABASE_URL`
- `VITE_SUPABASE_ANON_KEY`

דחיפה ל-`main` מריצה את `.github/workflows/deploy.yml`. בלי הסודות של Cloudflare הבנייה עוברת והפריסה מדולגת. אל תעלו תיקיית `dist` שנבנתה אצלכם: הבנייה המקומית כוללת את טלפוני אנשי הקשר, ובניית GitHub לא.

## אבטחה

אין התחברות. ב-Supabase, RLS כבוי וה-bucket ציבורי.

זה [CWE-306](https://cwe.mitre.org/data/definitions/306.html) (Missing Authentication for Critical Function), וב-OWASP זו גישה שבורה (A01 Broken Access Control). מי שמחזיק ב-anon key יכול לקרוא ולשנות כל הוצאה, משימה, איש קשר וקובץ.

זה מתאים כל עוד האתר פנימי והמפתח לא יושב במאגר הציבורי. לפני שהכתובת נעשית פומבית צריך התחברות ומדיניות גישה אמיתית.
